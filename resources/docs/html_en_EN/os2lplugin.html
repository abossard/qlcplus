OS2L plugin

Introduction

The OS2L (Open Sound 2 Light) plugin allows direct communication between QLC+ and an OS2L capable host.
The OS2L specification is published at https://os2l.org and defines a JSON-over-TCP protocol for DJ software to send lighting control messages.
The main OS2L host supported today is VirtualDJ; its OS2L implementation is documented at https://www.virtualdj.com/wiki/OS2L.html.
QLC+ OS2L plugin will work either on the same host (127.0.0.1) or on a different host with an OS of your choice (Windows, macOS, Linux).

New Features

The enhanced OS2L plugin now includes:

  • Automatic Service Discovery: Uses Bonjour/mDNS (RFC 6762 / RFC 6763) to automatically discover VirtualDJ and other OS2L-compatible software on your local network, searching for the _os2l._tcp.local. service type
  • Enhanced Logging: Displays all incoming OS2L messages with detailed information in the console output (source: OS2L spec)
  • Song Metadata: Extracts and logs song information — name, artist, album, BPM, key, elapsed time, duration, genre, deck number, and more (source: VirtualDJ OS2L wiki / OS2L spec)
  • Bidirectional Communication: Support for sending feedback messages back to VirtualDJ — see the VirtualDJ OS2L documentation for the list of supported output commands (experimental)
  • Beat Detection: Receives and processes beat messages for synchronization (source: OS2L spec)

Configuration - Virtual DJ

Step 1: Configure VirtualDJ
First and foremost, you need to tell VDJ where to send OS2L messages.
Open VDJ settings, go to the 'Options' panel and type 'os2l' in the top search box.
Modify the 'os2lDirectIp' field by setting the IP:port where VDJ can reach QLC+. For example, '127.0.0.1:9996' should work if QLC+ runs on the same (Windows) PC of VDJ.
Once done, restart VDJ.

Step 2: Enable OS2L in QLC+
Now go to QLC+, enable the OS2L plugin on any universe (Input/Output panel). If you have set a specific port in VDJ, open the OS2L configuration dialog and set the same port there.
Once done, QLC+ will start receiving signals from VDJ (joystick icon will blink beside the Universe box)

Step 3: Check the logs
If you run QLC+ with the -d flag (debug mode), you will see detailed logs of all OS2L messages:

  • Service discovery announcements when VirtualDJ is detected on the network
  • All JSON message fields and their values
  • Song metadata when tracks change (song name, artist, BPM, key, etc.)
  • Beat messages for synchronization
  • Button and command events

Automatic Service Discovery (Bonjour/mDNS)

The plugin now automatically discovers OS2L services on your local network using Bonjour/mDNS. When VirtualDJ or another OS2L-compatible application starts on your network, the plugin will detect it and log the discovery. This makes setup easier as you don't need to manually configure IP addresses.

Look for messages like:
[OS2L Discovery] Found OS2L service announcement from 192.168.1.100
[OS2L Plugin] Auto-discovered service: OS2L@192.168.1.100 at 192.168.1.100:9996

Song Metadata Display

When VirtualDJ sends a song event (as defined in the OS2L specification and the VirtualDJ OS2L wiki), the plugin will log all available metadata fields: 

[OS2L] ==================== SONG METADATA ====================
[OS2L] Song Name: Shape of You
[OS2L] Artist: Ed Sheeran
[OS2L] Album: ÷ (Deluxe)
[OS2L] BPM: 96.0
[OS2L] Key: 8B
[OS2L] Elapsed: 32.5 seconds
[OS2L] Duration: 233.7 seconds
[OS2L] Deck: 1
[OS2L] ======================================================
Supported song event fields (source: VirtualDJ OS2L wiki / OS2L spec):
FieldTypeDescription
namestringTrack title
artiststringArtist name
albumstringAlbum name
genrestringMusic genre
yearstringRelease year
remixstringRemix/edit version
statusstringPlayback status: play, pause, or stop
bpmnumberBeats per minute (float)
keystringMusical key in Camelot notation (e.g. 8B)
elapsednumberElapsed playback time in seconds
durationnumberTotal track duration in seconds
deckintegerDeck number (1 or 2)

This information can be used to trigger lighting cues based on song changes, BPM, or other metadata.

Feedback Commands (Output to VirtualDJ)

The plugin supports sending OS2L feedback messages back to VirtualDJ. The full list of supported commands is documented at https://www.virtualdj.com/wiki/OS2L.html. Examples:

  • /os2l/button "<name>" — trigger a named button
  • /os2l/midi/cue N — trigger cue point N
  • /os2l/midi/play_pause — toggle playback
  • /os2l/sampler/slot N play — trigger sampler slot N
  • /os2l/crossfader <value> — set crossfader (0.0–1.0)

References

  • OS2L Official Specification — primary source for all OS2L message types and protocol details
  • VirtualDJ OS2L Documentation — VirtualDJ-specific implementation, song metadata fields, and feedback commands
  • RFC 6762 — Multicast DNS — defines the mDNS protocol used for Bonjour service discovery (UDP port 5353, multicast 224.0.0.251)
  • RFC 6763 — DNS-Based Service Discovery — defines the _service._tcp.local. naming convention; the OS2L service type is _os2l._tcp.local.
  • Apple Bonjour — Apple's brand for mDNS+DNS-SD; on macOS the native APIs are DNSServiceBrowse / DNSServiceResolve from <dns_sd.h>
  • RFC 1035 — DNS Wire Format — binary packet format used when constructing mDNS query packets
